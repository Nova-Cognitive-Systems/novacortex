# Agent rules — NovaCortex

Rules for any human or AI agent committing to this repository.

## Commit identity (enforced in CI)

Every commit on this repository **must** be authored as the project bot, `Nova-DevBot`.

| Field | Allowed value |
|-------|---------------|
| `author.name` | `Nova-DevBot` |
| `author.email` | `dev@novacognitive.com` **or** `298337751+Nova-DevBot@users.noreply.github.com` |

Either email is accepted; any other `author.name` or `author.email` is rejected. Never
commit under a personal human identity (that includes personal Thorsten accounts) on this
repository.

Set it once per clone:

```bash
git config user.name  "Nova-DevBot"
git config user.email "dev@novacognitive.com"
```

Or per invocation, which is the safer default for automation:

```bash
GIT_AUTHOR_NAME="Nova-DevBot" \
GIT_AUTHOR_EMAIL="dev@novacognitive.com" \
GIT_COMMITTER_NAME="Nova-DevBot" \
GIT_COMMITTER_EMAIL="dev@novacognitive.com" \
  git commit -m "…"
```

The **committer** may differ from the author — GitHub sets itself as committer when a PR
is merged or a change is committed through the web UI, and merge commits are therefore
skipped by the check. The **author** is what is enforced.

The `Commit identity` workflow (`.github/workflows/commit-identity.yml`) runs on every
pull request and on every push to `main`, inspects the non-merge commits being introduced,
and fails with the offending SHA and identity if any author falls outside the allowlist
above. Fix a rejected commit by re-authoring it:

```bash
git rebase --exec 'git commit --amend --no-edit --reset-author' <base>
git push --force-with-lease
```

## Scope hygiene

Keep pull requests to one concern. Do not fold unrelated work (deployment variants,
Unraid/Community Applications packaging, dependency bumps) into a change that is about
something else.

## Secrets

Never commit secrets, license signing keys, or `.env` files. Secrets are generated by
`scripts/gen-env.sh`; see [SECURITY.md](./SECURITY.md).
